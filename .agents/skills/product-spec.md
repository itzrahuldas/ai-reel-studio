# Skill: Product Specification

## How to Write a Product Spec

A product spec answers: **What are we building, for whom, and why?**

## Required Sections
1. **Problem Statement** — What pain does this solve?
2. **Target Users** — Personas with context
3. **MVP Scope** — What is included
4. **Non-Goals** — What is explicitly excluded
5. **User Stories** — Written as: "As a [user], I can [action] so that [benefit]"
6. **Success Metrics** — Measurable, time-bound
7. **Product Risks** — Severity + mitigation

## Writing Rules
- Keep sentences short and declarative
- Every feature must map to at least one user story
- Non-goals must be as explicit as goals
- Success metrics must be testable in production

## Approval Loop
1. Draft written by Product Manager agent
2. Reviewed by System Architect (feasibility check)
3. Reviewed by Security Engineer (compliance check)
4. Approved before any implementation begins
5. All changes to scope must update the spec + CHANGELOG
